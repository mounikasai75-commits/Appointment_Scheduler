# Assumptions and Booking Invariant

- Appointment timestamps are UTC. The API accepts ISO 8601 timestamps ending in `Z` or `+00:00`; local time and non-zero offsets are rejected.
- Intervals are half-open `[start, end)`, and end must be strictly later than start.
- A provider cannot have overlapping active appointments. Exact adjacency is allowed, and different providers are independent.
- Cancelled appointments no longer block their interval.
- Appointment IDs are generated by the service. Blank provider IDs, empty cancellation IDs, and invalid timestamps are rejected without changing appointments.
- Provider IDs are compared ordinally and case-sensitively.
- The store is in memory and scoped to one API process; restarting the process clears it.
